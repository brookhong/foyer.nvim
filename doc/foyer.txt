1. INTRODUCTION                                           *foyer-introduction*

*foyer.nvim* runs your terminal coding agents, one per project, and puts a
normal, modifiable buffer in front of each. You write a prompt with the full
power of Vim, with a selection or an `@` mention of your code if you like,
press <CR>, and the agent gets it as one prompt; the same key later shows how
it is getting on. Any other terminal program, a shell or gdb, takes a prompt
the same way.

A foyer is the room you pass through on the way in. Nothing reaches the
terminal until you are done with it here.

It also keeps a persistent prompt history per terminal, and can edit a visual
selection in a scratch window.

The plugin defines no global mappings. See |foyer-api| and wire up the
functions you want, for instance: >lua
    local foyer = require('foyer')
    -- Pick a terminal by its key and write a prompt for it; from Visual
    -- mode the prompt carries the selected lines.
    vim.keymap.set({ 'n', 'v' }, '<leader>a', foyer.prompt,
        { desc = 'Prompt a picked terminal' })
    -- Edit the Visual selection in a floating buffer.
    vim.keymap.set('v', 'E', foyer.edit_selection)
    -- Any window, foyer's among them, to full screen and back.
    vim.keymap.set('n', '<leader>z', foyer.toggle_full_size)
    -- Any tab, window, buffer or recent file, by its label.
    vim.keymap.set('n', '<leader>b', foyer.jump)
<

3. SETUP                                                         *foyer-setup*

                                                               *foyer.setup()*
setup({opts})

{opts} is a table with the following keys. All are optional.

commands ~
    Table of terminals, keyed by the single character that selects them in
    |foyer.prompt()|. Each value is one of:

    - a string: the command to run, e.g. `'zsh'`
    - a table `{ command, arguments }`; the first element doubles as the
      display name in the window title
    - a function `f(project_root, launch_info)` returning either of the
      above, called every time, so the terminal can depend on the
      project: >lua
        e = function(project_root, launch_info)
            if project_root:find('kernel', 1, true) then
                return { 'bash', '--norc' }
            end
            return 'zsh'
        end,
<
    A table entry may also name, alongside its two elements:

    cwd       Directory the terminal is spawned in, instead of the project
              root.
    win_type  `'float'` opens its prompt in a float; the default is a split
              beside your code. A call's own `win_type` wins.
    scope     `'global'` keeps one terminal for the whole session instead of
              one per project. Its prompt takes the current window, and
              closing it hands the window back. >lua
        commands = {
            z = { 'zsh', win_type = 'float' },
            a = { 'opencode', '-c' },
            F = { 'opencode', '-c --agent counselor',
                  cwd = vim.env.HOME, scope = 'global' },
        }
<
root_markers ~
    Directory markers locating the project root, as |vim.fs.root()| takes
    them. Defaults to `vim.g.root_markers`, then `{ '.git' }`.

bracketed_paste ~
    Whether a multi-line send is wrapped in bracketed paste, see
    |foyer-limitations|. Defaults to `true`.

picker_delay ~
    Milliseconds |foyer.prompt()| waits for a terminal key before showing
    its picker; a key typed within it shows none. Defaults to `500`.

selection_max_lines ~
    A selection is sent with its lines up to this many, and as its label
    alone beyond, see |foyer-opts|. `0` never sends the lines. Defaults to
    `40`.

mention ~
    Whether `@` in a prompt lists files to mention, see |foyer-mention|.
    Defaults to `true`.

notify_status ~
    Whether foyer tells you, with |vim.notify()|, that a terminal's program
    is done, waiting for you, or failed, unless that terminal is in view.
    Only a program that reports its state, such as pi, says so; see
    |FoyerStatus|. Defaults to `true`.

normal_on_submit ~
    Whether a prompt typed straight into a terminal and sent with <CR> takes
    you back to Normal mode, on the last line, once its program reports it
    is working on it. Only a program that reports its state, such as pi,
    says so; see |FoyerStatus|. Defaults to `true`.

quit_guard ~
    Whether quitting Neovim is refused while a terminal of foyer's is busy:
    reporting that it works or waits for you, or else printing still. The
    error names it; `:qa!` quits anyway. Defaults to `true`.

tabline ~
    Whether foyer draws the tab line, like Neovim's own with each tab page's
    mark from |foyer.tab_mark()| in front, when 'tabline' is empty. Defaults
    to `false`.

keys ~
    The keys foyer maps in its own buffers, by action: `prompt` for a
    prompt, `terminal` for a terminal foyer started, see |foyer-mappings|.
    Only the actions named change. An action takes a key or a list of keys,
    put in the modes it has by default; a table by mode, naming the modes
    itself; or `false`, for no key. A list replaces the default list. The
    defaults: >lua
        keys = {
            prompt = {
                send = { n = '<CR>', i = '<C-s>' },
                close = { n = '<C-c>' },
                close_if_empty = { n = '<Esc>' },
                terminal = { n = '<C-o>' },
                history_prev = { n = { '<Up>', '<C-p>' }, i = '<Up>' },
                history_next = { n = { '<Down>', '<C-n>' }, i = '<Down>' },
                history_pick = { n = '<C-f>', i = '<C-f>' },
            },
            terminal = {
                alternate = { n = '<C-t>' },
                prompt = { n = '<C-o>' },
                split_prompt = { n = 'O' },
                close = { n = { '<CR>', '<C-c>', '<Esc>' } },
                cd_root = { n = '<C-r>' },
            },
        }
<
prompts ~
    Prompts of your own, by `commands` key, listed first in that terminal's
    <C-f> picker, in the order given, see |foyer-history|. Defaults to
    none. >lua
        prompts = {
            a = { 'review the staged changes', 'explain this error' },
        }
<
jump ~
    For |foyer.jump()|: `characters`, the keys its hint labels are made of
    (default `'asdfgqwertzxcvb'`), which also label the prompts <C-f> lists;
    `max_entries`, how many entries it lists at most (default: one per
    character, so each label is one key; more get labels of two);
    `backdrop`, the 'winblend' of the backdrop behind it, or `false` for none
    (default `60`); and `fallback`, a function for a key that is no label
    (default: Telescope's oldfiles if installed, else |vim.ui.select()| over
    the listed buffers and |v:oldfiles|).

                                                                  *foyer-opts*
                                                           *foyer.launch_info*
launch_info ~
    The context a prompt was composed with, captured by |foyer.prompt()| and
    |foyer.send()| and passed to a `commands` function. Passing one yourself
    skips the capture. >lua
        {
            project_root = '/repo',
            current_file = 'src/main.c',   -- relative to project_root
            current_line = 88,
            start_line = 30,  -- visual mode only
            end_line = 36,    -- visual mode only
        }
<
    With no project root, `project_root` is absent and `current_file` is
    absolute. In a buffer that is no file on disk the table is empty. Any
    other key you add reaches the function too.

Command {opts} accepted by |foyer.prompt()| and |foyer.send()|:

    command       Send this text instead of opening a prompt.
    interactive   Open the prompt even with `command` set, which then
                  seeds it.
    selection     Text appended to the prompt as it is sent. Set for you
                  when the send starts in Visual mode, see below.
    win_type      `'float'` for a float; otherwise a split. Wins over the
                  terminal's own `win_type`; ignored for a global terminal.
    auto_start    Spawn the terminal if it does not exist yet, see
                  |foyer-sending|.
    launch_info   See |foyer.launch_info|.

|foyer.prompt()| also accepts:

    key           The `commands` key to drive, instead of asking for one.
    show          Show the terminal in the current window rather than opening
                  a prompt for it, and return its buffer.

Starting from Visual mode attaches the selection, for an agent to read: a
shell would run its label. The prompt opens with the selection's place in its
title -- `src/main.c:30-36` -- and the selection is added below what you write
as it is sent: >
    what does this do?

    Selected in my editor: /repo/src/main.c, lines 30-36
    ```c
    ...the selected lines, as the buffer has them...
    ```
<
The label says when the buffer has unsaved changes. Past
`selection_max_lines` only the label is sent. A buffer that is no file on
disk -- unnamed, not saved yet, a scratch buffer, a terminal -- sends its
lines, labelled for what it is, and past `selection_max_lines` a temporary
file holding them, which the label names. A selection alone sends nothing;
a `selection` you pass yourself is appended as given.

Foyer reuses the split or float it already has open rather than opening
another. Launching a different terminal hands it to that terminal's prompt;
each terminal's draft is kept and comes back with it. A terminal's window
in another tab page moves to this one, draft and all. A terminal still
producing output is shown instead of a prompt, see |foyer.is_idle()|, and a
selection is then dropped, with a notice.

                                                               *foyer-sending*
A send to a terminal still starting waits until it is ready, with a notice;
its prompt opens at once, so the writing does not wait. A terminal's first
prompt gets its Enter only once its text shows on screen. A program that
starts on a question of its own -- trust this folder, a login -- is never
answered for you: foyer says so, and sends no Enter, nor anything queued
after it. Answer the question in the terminal; the prompt is in history, one
<Up> away.

4. API                                                             *foyer-api*

                                                              *foyer.prompt()*
prompt({opts})
    Wait for a `commands` key, spawn that terminal if it is not running for
    the current project, then open a prompt for it. With no key typed within
    `picker_delay`, a popup lists the keys, tagging global terminals
    `global`, marking running ones `●` and what one that reports its state
    is doing, see |FoyerStatus|. <Esc> or CTRL-C cancels.
    `opts.key` names the terminal outright, and `opts.show` steps into its
    buffer instead of opening a prompt.

                                                                *foyer.send()*
send({term_key}, {opts})
    Drive a specific terminal without prompting for a key. With
    `opts.command` set, the text is sent non-interactively; otherwise a
    prompt opens. With `opts.auto_start` the terminal is created if it is
    missing.

                                                  *foyer.alternate_terminal()*
alternate_terminal()
    Switch to the terminal of this project used last before the current one,
    in the same window: with two, a toggle. Each terminal's draft is kept.
    Global terminals are left out, and none is started. Mapped to
    `keys.terminal.alternate`, <C-t>, in foyer's terminals.

                                                      *foyer.edit_selection()*
edit_selection()
    Open the current visual selection in a floating buffer and replace the
    selection with the result. Must be called from Visual mode.

                                                    *foyer.toggle_full_size()*
toggle_full_size()
    Toggle the current window between full screen and the size it had: a
    float in height, a split both ways. Toggling back puts every split in the
    tab page back as it was. A neighbouring split keeps its minimum size, so
    a split may stop a little short. No key is mapped to it: >lua
        vim.keymap.set('n', '<leader>z', require('foyer').toggle_full_size)
<
                                                                *foyer.jump()*
jump()
    Jump to a tab, window, buffer or recent file by typing the hint label
    drawn over it. Tab pages are laid out with their windows as on screen,
    then the buffers no window shows, by when they were last used, then
    recent files, each name shortened to what tells it apart, up to
    `jump.max_entries`: the title says how many buffers were left out, and
    the fallback reaches them. A label goes to a window, or opens a buffer or
    file in this one; with Shift, a window's buffer comes into this window,
    and a buffer or file opens in a new tab.
    <BS> starts the label again, <Esc> cancels, and any other key hands over
    to `jump.fallback`. Windows squeezed flat are left out, and so are
    foyer's own terminals from the buffers. >lua
        vim.keymap.set('n', '<leader>b', require('foyer').jump)
<
                                                         *foyer.next_window()*
next_window()
    Move to the next window worth looking at, in CTRL-W w order, skipping
    floats and windows squeezed flat by a full-screen neighbour. With none
    left, switch to the alternate buffer instead, like CTRL-^. A maximised
    diff pane gives its pair back its size and steps into it.

                                                            *foyer.tab_mark()*
tab_mark({tabnr})
    The mark of tab page {tabnr}: `✓` when an agent there is done, `?` when
    one waits for you, `✗` when one failed, the most urgent first, or `''`.
    An agent's tab page is the one showing it or its prompt, else the one it
    was last used in. A tab page is marked only while you are in another, and
    entering it clears the mark; so does going to the agent from anywhere,
    or its working again. For a tab line of your own, put it in each tab
    page's label, or read the state from `vim.t.foyer_status`; or let foyer
    draw one, see `tabline`.

                                                             *foyer.is_idle()*
is_idle({buf}, {threshold_ms})
    Return true when {buf} has produced no output for {threshold_ms}
    milliseconds (default 1000). A program that reports its state is busy
    while working or waiting for you, and idle once done. A busy terminal is
    shown instead of a new prompt.

                                                                 *FoyerStatus*
A program that reports its state with the Program Status Protocol (OSC 7501),
such as pi, does so in foyer's terminals with no setup. Each change is a
|User| event `FoyerStatus`, with `data` = `{ buf, key, project, state,
message }`: `state` is `working`, `blocked` (waiting for you), `done`,
`error`, `idle`, or `clear` once it stops reporting; `project` is nil for a
global terminal. For a notification outside Neovim, for example: >lua
    vim.api.nvim_create_autocmd('User', { pattern = 'FoyerStatus',
        callback = function(ev)
            if ev.data.state == 'done' then
                vim.system({ 'osascript', '-e',
                    'display notification "done" with title "foyer"' })
            end
        end })
<

5. MAPPINGS                                                   *foyer-mappings*

All mappings below are buffer-local, each set by the `keys` action named
beside it, see |foyer-setup|. |foyer.edit_selection()|'s window takes `send`,
`close` and `close_if_empty` from `keys.prompt`.

In the prompt ~

A new prompt with something in it already -- a seeded `command`, a selection
to carry -- opens in Insert mode; an empty one in Normal mode.

    <CR>              n    Send the buffer to the terminal (`send`)
    <C-s>             i    Send the buffer to the terminal (`send`)
    <C-p>, <Up>       n    Previous history entry (`history_prev`)
    <C-n>, <Down>     n    Next history entry (`history_next`)
    <Up>, <Down>      i    Previous / next history entry, from the first /
                           last line (`history_prev`, `history_next`)
    <C-f>             n i  List the most used prompts, see |foyer-history|
                           (`history_pick`)
    @                 i    Mention a file, see |foyer-mention|
    <Esc>             n    Close the window if the buffer is empty
                           (`close_if_empty`)
    <C-c>             n    Close the window, discarding the draft (`close`)
    <C-o>             n    Show the prompt's terminal (`terminal`)

<C-o> toggles between a prompt and its terminal, in the same window. After a
send, the terminal takes the window and its prompt is empty.

                                                               *foyer-history*
History is kept per terminal, in `stdpath('cache')/foyer.json`, across
restarts. Typing first filters it to the entries containing what you typed,
highlighted with |hl-FoyerMatch|. In Insert mode <C-p> and <C-n> are
completion's, and <Up>/<Down> move the cursor in a draft of many lines until
it is on its first or last line.

<C-f> lists history by how often and how recently each prompt was sent, in a
popup at the cursor, each behind a hint label made of `jump.characters`. A
label puts its prompt in at the cursor; with Shift it replaces the draft.
Nothing is sent until you send it. The list is not filtered by the draft.

Prompts of your own, from `prompts`, come first, in the order given, each
always behind the same label, and marked `★`.

`/` in the list filters it, over the whole history, to the prompts holding
every word you type, in any order, ignoring case. <BS> takes a character
back, <C-w> a word, <C-u> the lot. <CR> goes back to picking among what is
left; <Esc> clears the filter, and then closes the list.

                                                               *foyer-mention*
`@` at the start of a word lists the open files, the one you came from first,
at your cursor line, then recent files (|v:oldfiles|). Typing after the `@`
searches them by name. While it is open:

    <CR>       Put in `@src/parser.c:120`, the path as the agent resolves it.
    <C-l>      Put in the selection block a Visual selection sends, see
               |foyer-opts|: the file's last Visual selection if it holds the
               line, else the line alone.
    <Esc>      Leave the `@` as typed.

In the terminal buffer ~

In foyer's terminals, in Normal mode; nothing is mapped in Terminal mode,
where every key is the program's:

    <C-t>              n   |foyer.alternate_terminal()| (`alternate`)
    <C-r>              n   cd to the terminal's project root (`cd_root`)
    <C-o>              n   Back to the prompt the terminal was shown for;
                           elsewhere, Vim's |CTRL-O| (`prompt`)
    O                  n   The prompt in a split above, the terminal kept
                           in view (`split_prompt`)
    <CR>, <C-c>, <Esc> n   Close the terminal window (`close`)

The split starts in Insert mode, with the draft <C-o> would show, if any.
It holds only the prompt, and closes with the terminal's window. Sending
closes it; <C-o> goes between it and the terminal below.

Yanking in a terminal strips the trailing whitespace a terminal pads lines
with. A terminal foyer has shown or sent to keeps its newest output in view.

6. HIGHLIGHTS                                               *foyer-highlights*

                                                               *hl-FoyerMatch*
FoyerMatch
    What the draft matches as <Up> walks history, and the words a `/` filter
    matches in the <C-f> list. Defaults to `bg=#333333 fg=#ff7700 bold`.

                                                            *hl-FoyerBackdrop*
FoyerBackdrop
    The veil dimming the editor behind the |foyer.prompt()|
    picker; needs 'termguicolors'. Defaults to `bg=#000000`.

                                                            *hl-FoyerTerminal*
FoyerTerminal
    The window of a foyer terminal in Terminal mode, where your keys go to
    the program. Defaults to the |hl-Normal| background, darker; link it to
    |hl-Normal| to leave the window alone.

|foyer.jump()| has its own, with a palette for each 'background':

    FoyerJumpTitle          section titles
    FoyerJumpName           buffer, window and file names
    FoyerJumpCurrent        the current buffer or window
    FoyerJumpNoName         buffers without a file name
    FoyerJumpTerminal       terminals foyer started
    FoyerJumpLabel          hint labels
    FoyerJumpLabelTyped     the part of a hint label already typed
    FoyerJumpBackdrop       dims the editor behind it, see `jump.backdrop`

All are defined with `default = true`, so your colorscheme or
|nvim_set_hl()| wins; set them from a |ColorScheme| autocmd, since a
colorscheme change clears them.

==============================================================================
7. LIMITATIONS                                             *foyer-limitations*

- A send of many lines is wrapped in bracketed paste, so the program takes
  its newlines as text, not Enter. Set `bracketed_paste = false` for one that
  shows the `[200~` escapes instead.
